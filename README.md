# SOCKS5 Proxy

یک پروکسی **SOCKS5** سبک و ساده با احراز هویت نام‌کاربری/رمزعبور، نوشته‌شده فقط با کتابخانه استاندارد پایتون (`asyncio`) و بدون هیچ وابستگی خارجی.

## ویژگی‌ها

- پیاده‌سازی پروتکل SOCKS5 مطابق [RFC 1928](https://datatracker.ietf.org/doc/html/rfc1928)
- احراز هویت با نام‌کاربری و رمزعبور مطابق [RFC 1929](https://datatracker.ietf.org/doc/html/rfc1929)
- پشتیبانی از آدرس مقصد از نوع IPv4، IPv6 و نام دامنه
- معماری غیرهمزمان (async) برای مدیریت هم‌زمان اتصال‌های زیاد
- مقاوم در برابر خطا: در صورت بروز خطای جدی، سرور پس از ۵ ثانیه خودکار راه‌اندازی مجدد می‌شود
- خاموش‌شدن تمیز با سیگنال‌های `SIGTERM` و `SIGINT`
- لاگ‌گیری ساده از اتصال‌ها، خطاها و تلاش‌های ناموفق ورود
- بدون نیاز به نصب هیچ پکیجی

## پیش‌نیازها

- Python نسخه **3.11** یا بالاتر

## تنظیمات

تنظیمات در بخش `CONFIG` ابتدای فایل `app.py` قرار دارد:

| متغیر | مقدار پیش‌فرض | توضیح |
|---|---|---|
| `LISTEN_HOST` | `0.0.0.0` | آدرسی که سرور روی آن گوش می‌دهد |
| `LISTEN_PORT` | `30855` | پورت سرور |
| `PROXY_USER` | `YourUserName` | نام‌کاربری |
| `PROXY_PASS` | `YourPassword` | رمزعبور |
| `CONNECT_TIMEOUT` | `15` | مهلت اتصال به مقصد (ثانیه) |
| `BUFFER_SIZE` | `65536` | اندازه بافر انتقال داده (بایت) |
| `MAX_CONNECTIONS` | `500` | حداکثر اتصال هم‌زمان (فعلاً در کد اعمال نمی‌شود) |

> ⚠️ قبل از اجرا حتماً نام‌کاربری و رمزعبور پیش‌فرض را تغییر دهید.

## اجرا

```bash
python app.py
```

در صورت اجرای موفق، چنین پیامی در لاگ نمایش داده می‌شود:

```
SOCKS5 proxy listening on 0.0.0.0:30855
```

## تست

با `curl` می‌توانید کارکرد پروکسی را بررسی کنید:

```bash
curl --socks5-hostname YOUR_SERVER_IP:30855 \
     --proxy-user YourUserName:YourPassword \
     https://ifconfig.me
```

اگر همه‌چیز درست باشد، خروجی آی‌پی سرور پروکسی خواهد بود.

## تنظیم در برنامه‌ها

| مورد | مقدار |
|---|---|
| نوع پروکسی | SOCKS5 |
| آدرس | آی‌پی یا دامنه سرور |
| پورت | `30855` (یا مقدار تنظیم‌شده) |
| نام‌کاربری / رمزعبور | مطابق تنظیمات فایل |

## نحوه کار

1. **Greeting:** کلاینت روش احراز هویت را اعلام می‌کند و سرور فقط روش نام‌کاربری/رمزعبور را می‌پذیرد.
2. **Auth:** اعتبارسنجی نام‌کاربری و رمزعبور.
3. **Request:** دریافت درخواست `CONNECT` به همراه آدرس و پورت مقصد.
4. **Connect:** تبدیل نام دامنه به آی‌پی و برقراری اتصال به مقصد.
5. **Relay:** انتقال دوطرفه داده‌ها بین کلاینت و مقصد تا بسته‌شدن اتصال.

## محدودیت‌ها

- فقط دستور `CONNECT` پشتیبانی می‌شود (`BIND` و `UDP ASSOCIATE` پشتیبانی نمی‌شوند).
- ترافیک بین کلاینت و پروکسی **رمزنگاری نمی‌شود**؛ در SOCKS5 نام‌کاربری و رمزعبور به‌صورت متن ساده ارسال می‌شوند. برای امنیت بیشتر از یک تونل رمزنگاری‌شده (مثل SSH یا VPN) استفاده کنید.
- تنها یک جفت نام‌کاربری/رمزعبور پشتیبانی می‌شود.
- تبدیل دامنه به آی‌پی فقط به‌صورت IPv4 انجام می‌شود.

## نکات امنیتی

- رمزعبور قوی و منحصربه‌فرد انتخاب کنید.
- اگر نیازی به دسترسی عمومی ندارید، `LISTEN_HOST` را روی آدرس مشخص یا `127.0.0.1` بگذارید.
- از قرار دادن اطلاعات ورود واقعی در مخزن‌های عمومی (مثل GitHub) خودداری کنید.
